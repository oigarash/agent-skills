# Ingest Procedure

新しいソースを Wiki に取り込むときの詳細手順。

## 前提

- `AGENTS.md` と `wiki/index.md` を読み終えていること
- 対象ソースの所在を確認（`inbox/raw/` のファイル / URL / 貼り付けテキスト）

## 手順

### 1. ソース読み込み

- ファイルなら Read（PDF は `pages` 指定で分割可）
- URL なら WebFetch でコンテンツ取得
- 長大なら要点抽出に集中

### 2. 関連ページ候補の特定（最低3つ評価）

- `wiki/index.md` を走査し、タイトル・要約・タグから候補を抽出
- 必要に応じて `wiki/pages/` を Grep（キーワード・エンティティ名）
- 候補 0 件でも「なぜ無いか」を一度確認してから新規作成に進む

### 3. ページ作成 or 更新の判断

| 状況 | アクション |
|---|---|
| 同じ主題のページが既にある | 既存ページを更新（本文追記 / `updated` 更新 / `sources` 追記） |
| 部分的に関連するページがある | 新規ページを作成し、既存ページに `[[新ページ]]` を追記 |
| 全く関連がない | 新規ページを作成、`topics/` のハブがあればそこにも登録 |

テンプレートは `page-template.md` を使用。

### 4. 波及更新（重要）

1 ingest で複数ページに触れることを積極的に行う。目安: 新規1〜2、既存更新3〜10。
- 新規ページ中で言及した既存概念には `[[wikilink]]` を張る
- 相手側ページの「関連」セクションにも逆方向の wikilink を追加
- 古い記述と矛盾する場合は、古い側の `## Open Questions` に両論併記

### 5. index.md 更新

新規ページができたら `wiki/index.md` の該当カテゴリに1行追加:

```
- [[ノート名]] — 50字程度の要約 #tag1 #tag2
```

タグ索引セクションも更新。

### 6. ソースのアーカイブ

- ファイルソース: `inbox/raw/xxx` → `inbox/processed/xxx` に mv
- URL ソース: `inbox/processed/urls.md` のような集約ファイルに `- <日付> <URL> -> [[取り込み先ページ]]` を追記
- 貼り付けテキスト: 必要なら `inbox/processed/snippets/<日付>-<要旨>.md` に保存

### 7. log.md 追記

```
YYYY-MM-DD HH:MM [ingest] <ソース識別子> -> [[新規ページ]], [[更新ページ1]], [[更新ページ2]]
```

日時は `date '+%Y-%m-%d %H:%M'` で取得。

## ユーザへの報告

ingest 完了時、以下を短くまとめて報告:
- 作成/更新したページ（wikilink 形式）
- 追加した相互参照の数
- 検出した矛盾や未解決事項（あれば）
- processed/ に移動したソース

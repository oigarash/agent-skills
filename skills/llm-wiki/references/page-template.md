# Page Template（Obsidian 互換）

新規ページはこのテンプレートをコピーして作成する。

ファイル名はノートタイトルそのまま（日本語可、スペース可、禁則文字 `\ / : * ? " < > |` のみ避ける）。配置先は `wiki/pages/` が基本、カテゴリのハブページは `wiki/topics/`。

```markdown
---
aliases:
  - 別名1
  - 別名2
tags:
  - tag1
  - project/wiki
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - "inbox/processed/xxx.pdf"
  - "https://example.com/article"
---

# <タイトル>

## TL;DR
ページの最初に必ず置く。ここだけ読めば全体像が掴めること。

- 1〜3文の本質的要約（何であるか／なぜ重要か）
- 処理フロー・構造・ワークフローがある対象なら、俯瞰を箇条書きや簡潔な ASCII 図で
  （例: `準備 → 起動 → ループ → 集計` の4フェーズ）
- 詳細は後続セクションへ。必要なら `詳細は [[#アーキテクチャ]] 参照` のようにポインタを張る

## <詳細セクション群>
TL;DR を深掘り。自由な見出し構成。[[他ノート]] への wikilink を積極的に張る。

引用はソースの該当箇所を明記:
- 〜〜（sources[0] p.3）
- 〜〜（https://... ）

## 関連
- [[関連ノート1]]
- [[関連ノート2|表示名]]

## Open Questions
- 未解決の論点、矛盾、要調査項目
- 解決したらこのセクションから削除、または本文に反映
```

## TL;DR ファーストの理由

- LLM の query 時、最初に読む部分が意思決定（深掘りするか / 別ページへ行くか）を左右する
- ページが長大化しても冒頭だけで本質が伝わる
- プロセス・フロー系の対象は、詳細の前に俯瞰図を見せないと読者が迷子になる

**書き方の指針**:
- TL;DR に数字や固有名詞の羅列を詰め込まない。「構造と関係性」を優先
- フロー図は 5〜10 行程度の ASCII で収める。細部は詳細節に委ねる
- 後続セクションと重複しても構わない（TL;DR は独立して読める必要がある）

## 規約メモ

- `aliases` は検索・wikilink 解決に効く。日本語別名や英語名を積極的に入れる
- `tags` はネスト可（`project/wiki`, `reading/paper` など）
- `sources` はパス or URL。複数ソースから合成されたページは全部列挙
- 本文のリンクは Obsidian wikilink のみ（Markdown link `[text](path.md)` は使わない）
- 見出しリンクは `[[ノート名#見出し]]`
- 画像・PDF 埋め込みは `![[file.png]]` / `![[file.pdf]]`
